# SpotBugs JSpecify Support Issue Reproducer

This repository demonstrates that **SpotBugs does not recognize JSpecify `@Nullable` annotations** 
as overriding `@ParametersAreNonnullByDefault`, causing false positive `NP_NULL_PARAM_DEREF` warnings.

## Issue Summary

When using [Immutables](https://immutables.github.io/) `@Value.Immutable` with JSpecify null annotations:

1. Immutables generates a builder class annotated with `@ParametersAreNonnullByDefault` (JSR-305)
2. The builder's setter methods are annotated with `@Nullable` for nullable fields
3. **SpotBugs does not recognize JSpecify's `@Nullable`** as overriding the default non-null behavior
4. This causes SpotBugs to report `NP_NULL_PARAM_DEREF` when passing a nullable variable to the builder

The same code with **JetBrains `@Nullable`** works correctly - SpotBugs recognizes it and produces no warning.

## Code Comparison

### JSpecify (triggers false positive)

```java
@Value.Immutable
public interface JSpecifyData {
  @org.jspecify.annotations.Nullable  // JSpecify
  String nullableField();
  
  String requiredField();
}

// Usage:
public JSpecifyData create(@Nullable String maybeNull) {
  return ImmutableJSpecifyData.builder()
    .nullableField(maybeNull)  // SpotBugs: NP_NULL_PARAM_DEREF ⚠️
    .build();
}
```

### JetBrains (works correctly)

```java
@Value.Immutable
public interface JetBrainsData {
  @org.jetbrains.annotations.Nullable  // JetBrains
  String nullableField();
  
  String requiredField();
}

// Usage:
public JetBrainsData create(@Nullable String maybeNull) {
  return ImmutableJetBrainsData.builder()
    .nullableField(maybeNull)  // No warning ✓
    .build();
}
```

## Generated Bytecode Comparison

Both generate similar bytecode with `@Nullable` on the builder parameter:

```java
@ParametersAreNonnullByDefault  // JSR-305
public final class ImmutableJSpecifyData$Builder {
  public final Builder nullableField(@org.jspecify.annotations.Nullable String value) { ... }
}

@ParametersAreNonnullByDefault  // JSR-305
public final class ImmutableJetBrainsData$Builder {
  public final Builder nullableField(@org.jetbrains.annotations.Nullable String value) { ... }
}
```

**The only difference is the annotation class**, but SpotBugs only recognizes JetBrains.

## Running the Reproducer

```bash
./gradlew spotbugsMain
```

### Expected Output

```
M C NP_NULL_PARAM_DEREF: Null passed for non-null parameter of 
   ImmutableJSpecifyDataBuilder.nullableField(String) in 
   com.example.Main.createJSpecifyData(...) at Main.java:[line 28]
```

**No warning is reported for `createJetBrainsData()` or `createJSpecifyWithNullLiteral()`**.

## Workarounds

1. **Use JetBrains annotations** instead of JSpecify for nullable parameters
2. **Use literal `null`** instead of nullable variables
3. **Add `@SuppressFBWarnings("NP_NULL_PARAM_DEREF")`** to suppress the warning
